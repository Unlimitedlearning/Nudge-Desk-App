# 用户画像分析 (User Persona)

## 一、 目标客户群体划分

### 1. 核心用户（C端使用者）
- **群体定位**：18-24岁的重度伏案大学生（计科、设计、法学、医学等专业）。
- **特征**：每天在电脑前写代码、刷网课、写论文超过4小时，长期伏案。
- **核心痛点**：
  - 经常脖子酸痛、肩颈僵硬，出现轻微高低肩。
  - 极其反感打扰（如强制弹窗、刺耳的警报音效），需要的是“余光一瞥就能察觉”的温和提醒（轻微白噪音/震动）。
  - 对隐私有顾虑，对摄像头数据敏感，不信任强制联网的桌面软件。

### 2. 潜在用户（未来扩展）
- **群体定位**：13-18岁的高中生/初中生及其家长。
- **特征**：处于体态发育关键期，学业压力极大。
- **核心痛点**：防近视、防驼背。

### 3. B端买单者（远期商业方向）
- **群体定位**：高校辅导员、高校心理健康与健康管理中心。
- **核心痛点**：有“青少年近视防控”与“脊柱健康”的KPI考核，缺乏轻量级管理工具。

## 二、 典型用户画像（Persona）

### Persona 1：核心用户 —— “码农/学术党”小陈
- **身份**：大二计算机科学与技术专业学生。
- **日常**：每天4-6小时写代码、调试程序、看网课。喜欢戴耳机沉浸式工作。
- **痛点**：
  - 进入“心流”时脖子不自觉地前倾，一坐就是两小时。
  - 用过 PostureGuard 等软件，觉得弹窗太烦，直接卸载，因为会打断心流。
  - 对隐私有顾虑，不希望摄像头画面被录下来传上网。
- **产品诉求**：
  - 不需要弹窗和声音，余光扫一眼屏幕右下角就知道坐直了没有（颜色变化），偶尔一声轻柔的“叮”可以接受。
  - 视频数据必须是本地处理的，但允许在购买增值服务时联网验证。
  - 如果长时间保持好姿势，希望能有正向反馈（比如一个小奖励）。

### Persona 2：未来潜在用户 —— “陪读妈妈”刘女士
- **身份**：40岁，孩子上初二，每天陪孩子写作业。
- **痛点**：孩子弯腰驼背，视力下降，经常提醒容易引发亲子矛盾。
- **产品诉求**：希望有个工具默默帮孩子纠正，不唠叨、不打扰，还能记录每周坐姿数据。

### Persona 3：远期 B端用户 —— 高校辅导员/健康管理中心
- **身份**：负责学生健康管理的高校老师。
- **痛点**：国家有近视防控、脊柱健康的考核指标，但缺乏轻量级的数据抓手。
- **产品诉求**：希望拿到脱敏后的“班级体态健康看板”，能输出宏观报告。

## 三、 解决“隐私保护”与“联网盈利”的核心矛盾（架构声明）

本项目坚持 **“本地优先（Local-First）+ 脱敏同步”** 的架构：
1. **视频流 100% 本地处理**：MediaPipe 骨骼提取与夹角计算全在本地完成，绝对不上传任何视频画面。
2. **联网场景严格受限**：
   - **C端增值**：仅在购买/下载皮肤时联网验证一次，下载后纯本地使用。
   - **B端看板**：仅上传“脱敏后的元数据”（如：低头总时长、疲劳触发次数），绝不包含人脸或身份信息，且需用户主动授权开启。
3. **数据主权归属用户**：用户有权选择“纯离线模式”，仅使用本地提醒功能，不参与任何云端数据同步。

## 四、 如何指导后续开发？

| 功能 | 对应画像痛点 | 产品决策 |
| :--- | :--- | :--- |
| **防近视** | 小陈、刘女士、高中生的痛点 | 优先开发，通过距离检测提醒 |
| **高低肩检测** | 小陈歪身子找代码角度时的痛点 | 第二阶段开发 |
| **番茄钟联动** | 小陈需要温和的专注节拍 | 需做成“建议性”，不强制暂停 |
| **皮肤买断（C端增值）** | 小陈喜欢折腾桌面 | 核心功能免费，皮肤作为微营收 |
| **校园看板（B端授权）** | 辅导员、健康中心的痛点 | 算法成熟后，远期探索 |
