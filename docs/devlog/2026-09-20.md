# 2026年9月20日 开发日志

## 核心进展：系统逻辑消化与架构复盘

今天下午处理完学校和班级的杂事，终于有时间坐下来仔细重读这周写过的代码。顺着 `camera -> pose -> analysis -> ui` 的调用顺序，把每个文件都跑了一遍，对系统数据流有了更清晰的认识：

### 1. 数据流转路径
`app.py` 的 `process_frame` 每30ms执行一次：
- 先调 `camera.py` 获取录像帧；
- 传给 `pose.py` 做图像预处理和骨骼点提取（landmarks）；
- 再传给 `analysis.py` 计算夹角并累积疲劳值（result）；
- 最后推给 `ui.py` 渲染状态；
- 执行完后使用 `root.after(30, process_frame)` 递归调用自己，实现循环。

### 2. 对“事件驱动”的重新认识
之前我一直以为为了避免阻塞而使用了多线程，但复盘后发现，代码并没有使用 `threading`，而是利用了 `tkinter` 的 `root.after` 回调机制。这种方式让所有任务都在同一个UI主线程中执行，避免了多线程的锁竞争与线程安全问题。

### 3. 关于疲劳值系统与边界情况的思考
`analysis.py` 中的变量 `dt` 是“当前时间 - 上一次检测的时间”，根据这段时间差动态判断加减 `bad_score`（疲劳度）。
如果 `read()` 返回 `None`，目前程序会跳过该帧，但未来如果摄像头长时间断开，程序会空转，悬浮窗会卡在上一状态。这是后续需要优化的点

### 4. 完成模块级注释
给五个核心文件头部加上了功能注释，明确各自职责。随着后续函数增多，模块化清晰是维护代码的第一步。
